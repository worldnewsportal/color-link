# Color Link — Phase 1

A mobile-first colour-matching path puzzle, built as a plain HTML5 / CSS3 / ES6 web app.
Connect every pair of identical dots with a continuous path that never crosses
another path. No backend, no ads, no in-app purchases, no runtime dependencies.

---

## 1. Quick start

```bash
# 1. serve the game locally (ES modules need http://, not file://)
npm run serve          # http://localhost:5173

# 2. run the static checks (imports, level catalogue, file layout)
npm run check

# 3. build the web app into public/ (the Capacitor webDir)
npm run build
```

Open `http://localhost:5173` on a phone (or in a mobile emulator) — the game is
designed for portrait phones, e.g. 393 × 851 (Pixel), 360 × 800, 412 × 915.

## 3. Gameplay rules

1. Each colour has exactly two endpoints.
2. A path moves only between orthogonally adjacent cells.
3. Two colours can never occupy the same cell and paths never cross.
4. Drag from a dot to its twin. Dragging back over your own path erases it.
5. A completed pair can be redrawn by dragging from one of its dots.
6. The level is finished when every pair is connected — detection is automatic.

Controls: drag with one finger (multi-touch is ignored), or with a mouse.
Undo, restart and hint are available in the top bar.

## 4. Levels

`src/data/levels.js` contains 30 hand-tuned-by-generator levels:

| Levels | Grid | Pairs | Difficulty |
|--------|------|-------|------------|
| 1–5    | 5×7 – 5×8 | 2 | easy |
| 6–10   | 6×8 – 6×9 | 3 | normal |
| 11–20  | 6×9 – 8×12 | 4–5 | hard |
| 21–30  | 7×11 – 9×14 | 6–7 | expert |

Every level is **constructively generated** (each pair is routed through the
still-free cells) and then **independently verified**:

* `tools/gen_levels.py` re-checks the emitted data with a separate checker
  (`verify_solution`) that proves every pair is connected by a non-crossing,
  obstacle-free, 4-adjacent path;
* a backtracking search solver (`solve`) additionally re-derives a solution
  from the endpoints alone — it never sees the reference solution;
* `src/core/level-manager.js` runs `validateLevel()` on all 30 levels at boot
  and logs a report to the console.

Regenerate the catalogue with:

```bash
python3 tools/gen_levels.py      # rewrites src/data/levels.js
```

## 5. Saving

`localStorage` key `colorlink.save.v1` holds:

* completed levels, highest unlocked level, last played level
* best time per level, total playtime, hints used, runs
* settings: sound effects, background music, vibration, language, theme

Access is wrapped in try/catch with an in-memory fallback, so private mode or
a disabled storage API never breaks the game.

## 6. Settings, languages, themes

* Sound effects / background music / vibration — all take effect immediately.
* Language: English or Arabic. Arabic switches the document to `dir="rtl"` and
  the layout follows (logical CSS properties are used throughout).
* Theme: light or dark — CSS custom properties on `<html data-theme>`.
* Reset progress asks for confirmation and keeps your language/theme choices.

## 7. Audio

All sound is synthesised with the WebAudio API (oscillators + envelopes), so
there are no audio files to download and nothing can break. The context is
unlocked on the first user gesture, as required by mobile browsers and WebViews.

## 8. Build the Android APK (Capacitor + GitHub Actions)

The repository contains a ready-to-run workflow: **Actions → Build Android APK**.
It installs the dependencies, runs the static checks, builds the web app into
`public/`, adds the Android platform, syncs the assets and uploads the debug
APK as a build artifact.

To build locally:

```bash
npm install
npm run build          # -> public/
npx cap add android    # first time only
npx cap sync android
npx cap open android   # or: cd android && ./gradlew assembleDebug
```

The APK is written to `android/app/build/outputs/apk/debug/app-debug.apk`.

Notes for a release build: set `appId`/`appName` in `capacitor.config.json`,
add a signing config in `android/app/build.gradle` and replace the launcher
icons in `android/app/src/main/res/`.

## 9. Quality assurance

An automated suite (`qa/test_color_link.py`) drives the real game in Chromium
with real pointer input — it does not poke at internals:

```bash
python3 -u qa/test_color_link.py      # 42 checks
```

What it covers

* every screen opens and closes, no placeholder buttons
* all 30 levels are **played to completion** with mouse drags along the
  reference solution → win detection, unlocking and saving are exercised
* undo removes the drawn cells, restart clears the board, the hint reveals a
  ghost path and decreases the counter
* locked levels refuse to open, completed levels can be replayed
* progress, language, theme and audio settings survive a reload
* Arabic switches the document to RTL
* reset asks for confirmation and really clears the save
* no horizontal overflow and the board always fits at 360×640, 393×851 and
  412×915
* no console or page errors during the whole run

Screenshots of every screen (dark / light / RTL) are produced by
`python3 qa/shots.py` into `qa/shots/`.

`npm run check` additionally validates the file layout, resolves every import
and re-checks the level catalogue (endpoints in bounds, no crossings, every
pair connected by the bundled solution).

Performance: the canvas only repaints when something actually changes (no
per-frame shadows), the device pixel ratio is capped at 2 and the board keeps
60 fps on the largest level.

## 10. Technical notes / limitations

* The game uses ES modules with relative paths only — no CDN, no network calls
  at runtime. `npm run build` injects a strict CSP into the shipped `index.html`.
* Audio starts only after the first tap (browser autoplay policy).
* Vibration uses `navigator.vibrate`, which Android WebView supports but
  desktop browsers ignore — the call is guarded.
* The level catalogue is generated offline; no level is randomised at runtime.
* Free hints are limited to 3 per level (no ads, no IAP in Phase 1).
